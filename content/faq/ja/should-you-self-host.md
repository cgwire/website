Kitsuは無料のオープンソースで、現在約400のスタジオが自社運用しています。ライセンス費用はかかりません。しかし、きちんと運用するにはコストがかかり、50人規模のスタジオでは多くの見積もりより大きな金額になります。

## 結論

2年間で、50人規模のスタジオが各選択肢に支払う金額は次のとおりです。

| 選択肢 | 2年間のコスト | チームに残る作業 |
|---|---|---|
| Kitsu Cloud Productionプラン | 36,000ユーロ（1ユーザーあたり月30ユーロ、年払い） | インフラ作業なし |
| Kitsu Cloud Studioプラン | 42,000ユーロ（1ユーザーあたり月35ユーロ、年払い） | インフラ作業なし |
| 本格的な自社運用 | 推定300〜600時間の運用作業とハードウェア | すべて |
| Partners付きの自社運用（16〜100ユーザー） | 7,000ユーロの拠出に加え、同じ時間とハードウェア | すべて（CGWireチームへの直接の窓口あり） |

自社運用の数字は、インスタンスが1人に依存しないよう訓練を受けた管理者が2名いること、そしてリストアが検証済みであることを前提としています。

両者を比較するには、Cloudの価格を時間で割ります。36,000ユーロを300時間で割ると1時間あたり120ユーロ、600時間なら1時間あたり60ユーロです。

スタジオで有資格の管理者にかかる人件費総額がこの水準を上回るなら、サーバーを1台も買う前から、本格的な自社運用はCloudより高くつきます。有資格のITスタッフを雇用しているほとんどのスタジオがこれに当てはまります。

それでもこの比較は自社運用に有利です。平均しか見ていないからです。本当の違いはばらつきにあります。

## なぜ平均コストで考えるべきではないのか

総所有コストの表は、毎月が平均的な月であることを前提にしています。実際の制作はそうはいきません。

火曜日にインスタンスが落ちれば、管理作業が数時間かかるだけです。しかし同じ障害が納品の2週間前に起きれば、レビューは止まり、タスクのステータスは固まり、スーパーバイザーが待つ間、管理者は他のすべての仕事から引き離されます。請求書上の時間は同じでも、制作へのコストは一気に膨らみます。

自社運用はうまく行うこともできます。問題は、スタジオがうまくいかない週を吸収できる体制になっているか、そしてその体制にいくらかかるかです。

## 時間はどこに消えるのか

以下の数字は、[自社運用ドキュメント](https://dev.kitsu.cloud/self-hosting/setup)に記載された手順をもとにした、50人規模のスタジオの2年間の推定値です。実際の数字は、インフラ、リリースの頻度、チームがすでにどこまで自動化しているかによって変わります。

| 作業 | 2年間の推定時間 | 根拠 |
|---|---|---|
| 初期インストールとハードニング | 40〜80 | Python、Node、PostgreSQL、Redis、Webサーバー、ジョブキュー、全文検索の手動セットアップ |
| アップグレードとZouのスキーママイグレーション | 50〜100 | Zouパッケージの更新、`zou upgrade-db`の実行、Kitsuフロントエンドの更新、事前のステージング検証。四半期に1回の計画的なサイクルを想定 |
| バックアップとリストアテスト | 50〜100 | データベースダンプとプレビューフォルダのバックアップの自動化、別のPostgreSQLインスタンスへの毎月のテストリストア |
| プレビューストレージ | 20〜40 | 容量計画とボリューム拡張。ドキュメントはアップロードされた全ファイルの2.5〜3倍の容量を推奨 |
| SSO | 10〜30 | LDAP、SAML、OIDCの設定と、IDプロバイダー変更時の保守 |
| セキュリティパッチ | 50〜100 | OS、PostgreSQL、Redis、PythonとNodeの依存関係、TLS証明書 |
| 監視とログローテーション | 40〜80 | アラート、ログ管理、定期チェック、障害の一次対応 |
| 2人目の管理者と運用手順書 | 40〜80 | 2人目の育成、手順書の更新、両者によるアップグレードとリストアの実施 |
| **合計** | **300〜600** | |

ハードウェアは別途かかります。31〜80ユーザーの場合、ドキュメントでは推奨最小構成として4コア、15GBのRAMを挙げており、データベースは別のVMに、プレビューフォルダは専用のボリュームに置くことになっています。

社内の見積もりでよく抜け落ちる項目が2つあります。リストアテストと2人目の管理者です。そしてこの2つこそが、障害時に表の残りが成り立つかどうかを決めます。

## リスクシナリオ

月平均には現れない状況です。どれも、2年間の制作で普通に起こりうる以上の不運を必要としません。

### マイグレーションが失敗する

Zouのアップグレードにはデータベーススキーマのマイグレーションが含まれます。途中で失敗した場合や、新しいバージョンがデータやカスタム連携に対して異なる動作をした場合でも、アップデートガイドにはダウングレードの手順がありません。戻す方法は、アップグレード前に取得したデータベースダンプを以前のバージョンのZouでリストアすることだけです。そのダンプを取っていなかったり、違うバージョンで取っていたりすれば、ロールバックは再構築になります。

### バックアップが一度もリストアされていない

ドキュメントには、データベースのリストアには元と先のAPIバージョンが一致している必要があり、そうでなければスキーマが合わない可能性があると記載されています。1年間、何度もアップグレードを重ねながら毎晩データベースをダンプし、一度もリストアしていないスタジオは、バックアップが機能するかどうかを知りません。プレビューファイルは、ドキュメントが選択を委ねているツールで別途バックアップされます。最初の本番リストアで初めて欠落が見つかることは珍しくありません。

### 管理者が退職する

自社運用のKitsuインスタンスには、さまざまな判断が積み重なっています。環境ファイルの場所、サービスの起動方法、使用しているストレージバックエンド、何をなぜカスタマイズしたか。これらを1人で決めていたなら、その人と一緒に失われます。公開Discordコミュニティは活発で親切ですが、新しく入った担当者に自社のインスタンスがどう構築されたかを教えることはできません。

### レンダリング中にプレビュー用ディスクが満杯になる

プレビューの容量は直線的には増えません。制作が最も多くの作業をアップロードする時期、つまり多くの場合は納品直前にピークを迎えます。プレビュー用ボリュームが満杯になると、アップロードとトランスコードが止まり、アーティストはレビューに作業を提出できなくなります。ボリュームの拡張は、落ち着いた日なら日常作業ですが、50人が待っている状況では大きなストレスになります。

### 締め切りに障害が重なる

復旧時間は、原因の調査、データベースのリストア、プレビューファイルの復元、連携の再接続の確認を合わせたものです。その間、スーパーバイザーはレビューできず、プロデューサーはステータスを確認できず、アーティストはフィードバックなしで作業します。このコストは制作日数で測られます。

## どの選択肢がスタジオに合うか

答えはインフラの好みではなく、チームの体制によって決まります。

- **専任のIT担当者がいない。** Kitsu Cloudを使ってください。責任者のいない自社運用では、上記のシナリオが誰も備えていない状態で起こります。
- **管理者が1人いる。** 自社運用は可能ですが、インスタンスは1人の都合と記憶に依存します。この道を選ぶなら、最低限[Partnersプログラム](/ja/partners)（16〜100ユーザーで年間3,500ユーロ）に参加し、問題が起きたときにCGWireチームへ直接相談できるようにしてください。そして、その依存をなりゆきではなく明確に受け入れてください。PartnersはSLA付きのサポート契約ではなく、Kitsuを開発している人たちへのアクセスです。
- **訓練を受けた管理者が2人いて、手順が文書化されている。** 自社運用は現実的です。「文書化されている」とは、アップグレードとリストアの手順書があり、リストアテストが定期的に行われ、2人とも実際にそれぞれの手順を実施したことがある状態を指します。自社環境を超える問題でチームに相談できるよう、Partnersは引き続き推奨します。

データを自社サーバーに置く必要があるものの、3つ目の条件に当てはまらない場合は、**マネージドオンプレミスがそのための選択肢です**。CGWireがお客様のインフラ上でKitsuを運用します。

## Cloudは節約ではなく保険

Kitsu Cloudは、平均的な月でもIT作業が高くつくからこそ、その作業をなくします。しかしそれ以上に、自社運用にともなうリスクをなくします。失敗したマイグレーション、検証されていないバックアップ、退職、満杯のディスク、締め切り直前の障害。これらのリスクは、多数のインスタンスを運用し、日常的に対処しているチームに移ります。

スタジオがこのばらつきを自ら引き受けられるなら、自社運用は正当な選択であり、多くのスタジオがうまく実践しています。本格的に自社運用するなら、Partnersが最低ラインです。

4つの選択肢の比較は[Cloud、Partners、自社運用型](/ja/機能/自社運用型)のページにあります。
